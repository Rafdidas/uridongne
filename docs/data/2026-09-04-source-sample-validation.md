- 점포·개업·폐업 관련 음수: 0건
- 점포·개업·폐업 관련 비정수: 0건

연도별 파일 하나에 4개 분기만 있으므로 단일 파일만으로는 5개 연속 분기를 만들 수 없다. 2024년 4분기부터 2025년 4분기까지 결합하면 5개 연속 분기 추이를 만들 수 있고, 2025년 각 분기의 전년 동분기도 존재한다.

## 생활인구 호환성

- 세 원본의 헤더·인코딩과 핵심 필드 이름은 같다. 핵심 필드는 `일자`, `시간`, `행정동코드`, `생활인구합계`다.
- 202607은 31개 일별 파일이지만 202507과 202606은 월 파일 1개다. 202607 내부에서도 데이터 행 구분자가 쉼표와 세미콜론으로 나뉜다.
- 날짜 범위는 각각 `20260701~20260731`, `20250701~20250731`, `20260601~20260630`이며 모두 0~23시가 존재한다.
- 행 수는 각각 `31×24×427=317,688`, `31×24×426=316,944`, `30×24×427=307,440`으로 해당 월의 날짜·시간·행정동 조합과 정확히 일치한다.
- `날짜 + 시간 + 행정동` 중복, 음수 생활인구, 비유한 생활인구는 세 원본 모두 0건이다.
- 결측 표기는 `*`이며 연령·성별 세부 열에서 202607 5,093건, 202507 3,426건, 202606 4,723건이다. `생활인구합계`에는 결측이 없다.
- 현재 엄격 비교 결과는 `comparisonMode: unavailable`, `fallbackReason: previous_month_schema_mismatch`다. 차이는 202607의 엔트리 31개와 비교 파일의 엔트리 1개라는 구성 차이 두 건이다.

내용 수준의 완결성은 확인했지만 현재 비교기는 파일 구성 정규화 전 단계다. 따라서 202607과 202507의 전년 동월 증감을 아직 계산하지 않으며, 202606 전월 비교로도 임의 대체하지 않는다.

## 행정동 코드

- 두 데이터셋 모두 문자열로 보존해야 하는 8자리 코드다. 이번 표본에는 선행 0이 없지만 숫자 변환은 허용하지 않는다.
- 상권 2025는 425개, 생활인구 202607은 427개 코드를 포함한다.
- 공통 코드는 422개다.
- 상권에만 있는 코드는 `11230536`, `11680740`, `11740520`이다.
- 생활인구에만 있는 코드는 `11230515`, `11230533`, `11680675`, `11740525`, `11740526`이다.

코드 차이는 행정동 개편 가능성을 보여주므로 기준일과 코드 유효기간을 결합하기 전에는 정상 증감으로 처리하지 않는다.

## 결정

- production 파서는 EUC-KR ZIP/CSV, 월 단일 파일과 일별 다중 파일, 파일별 구분자, 쉼표 헤더+세미콜론 행, CRLF/LF 혼합 입력을 지원해야 한다.
- 컬럼 계약은 CLI의 `--schema` JSON으로 명시하고, 실제 헤더와 다르면 즉시 실패한다.
- 상권 파서·집계 설계는 진행할 수 있다. 2024~2025 결합 시 전년 동분기 비교와 5분기 추이가 가능하다.
- 생활인구 전년 동월 비교는 파일 엔트리 경계를 제거한 월 단위 정규화와 행정동 코드 유효기간 검증을 먼저 구현해야 한다.
- D1 스키마 자체를 구체화할 근거는 확보했지만, 전체 D1 적재 계획은 생활인구 source-adaptation 검증이 끝날 때까지 보류한다.

다음 독립 작업 단위는 `월 단일 CSV ↔ 일별 다중 CSV`를 같은 월 관측 집합으로 정규화하고, 완결성과 코드 변경을 판정하는 source-adaptation 계획이다.
