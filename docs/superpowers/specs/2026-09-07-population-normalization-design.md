# 생활인구 월 정규화·비교 설계

작성일: 2026-09-07
상태: 합의한 정책을 반영한 설계 검토본. 코드 구현은 다음 모델 전환 이후 진행한다.

## 1. 목적과 범위

OA-23016 월 단일 CSV와 일별 다중 CSV를 동일한 관측 계약으로 읽고, 동별 월평균과 검증 결과를 생성한다. 파일 수·순서·구분자 차이가 통계 비교 가능성을 대신 판단하지 않도록 물리적 파일 검사와 의미적 비교를 분리한다.

이번 범위는 로컬 수집 도구, 월 집계, 비교 판정, 재현 가능한 결과 문서다. D1/R2 연결, 배포, 화면, 공식 분할·통합 환산은 후속 작업이다.

## 2. 합의와 선택한 구조

- MVP는 동일 행정동 코드끼리만 비교한다. 코드가 다르면 자동으로 이름 연결·비례 배분하지 않는다.
- 향후 공식 변경 이력의 버전·유효기간·근거를 수용한다. 근거가 확인된 1:1 변경 지원은 후속 구현이며 분할·통합 재집계도 이번에 수행하지 않는다.
- 원본 ZIP을 보존하고 정규화 시간별 전체 파일은 영구 저장하지 않는다. 읽는 동안 검증·집계하고 월 집계와 검증 매니페스트를 저장한다.

검토한 대안은 기존 프로파일 비교에서 파일 수 조건만 제거하는 방식과 정규화 전체 파일을 별도 보관하는 방식이다. 전자는 관측 결측·산출 방식 차이를 검증하지 못하고, 후자는 재처리 가능한 원본과 보관 대상을 중복한다. 선택한 구조는 원본 → 엔트리 순차 해독 → CSV 행 스트림 → 엄격한 관측 변환 → 동별 슬롯 검사·월 집계 → 비교 판정이다.

## 3. 기존 근거의 한계

2026-09-04 보고서의 317,688·316,944·307,440행과 기간·시간 범위, 중복 카운터는 측정값이다. 그러나 기존 코드는 시간 문자열을 그대로 중복 키로 사용하고 `Number`로 수치를 변환한다. `0`과 `00`의 동일 슬롯 중복, 빈 문자열이 0이 되는 문제, 잘못된 달력 날짜, 동 전체가 누락된 경우를 완전히 증명하지 못한다. 기존의 완결성 통과는 전체 규모 일치라는 예비 근거로 해석한다.

또한 상권 2025와 생활인구 202607 간 422개 공통 코드는 서로 다른 데이터셋 사이의 교집합이다. 이를 생활인구 202607과 202507의 전년 비교 대상 수로 사용하지 않는다. 코드 차이만으로 실제 개편 사실을 확정하지 않는다.

## 4. 입력 계약과 처리 경계

실행 입력은 원본 경로, 기대 연월 `YYYYMM`, source ID, 원본 SHA-256, 스키마 버전, 산출 방식 근거 ID, 선택적 공식 행정동 목록 버전이다. 월은 파일명에서 추정하지 않는다. 처리 시점은 명시적으로 전달하여 아직 끝나지 않은 월을 완결 월로 승인하지 않는다.

CSV의 승인된 32개 헤더 목록을 버전 관리한다. 중복·누락·예상 밖 헤더는 스키마 실패다. 핵심 매핑은 `일자`, `시간`, `행정동코드`, `생활인구합계`다. 세부 열의 `*`는 결측 통계에 기록하며 합계 필드를 대체하거나 연령 합으로 복원하지 않는다.

월 단일·일별 다중 파일, EUC-KR, 쉼표·세미콜론 데이터 행, 쉼표 헤더와 세미콜론 행의 조합, CRLF/LF를 명시적으로 지원한다. 따옴표를 인식하는 CSV 파서로 헤더를 처리한다. 엔트리 이름·순서는 출처 위치로 기록하며 비교 적격성 조건으로 사용하지 않는다. 알 수 없는 비디렉터리 엔트리는 조용히 버리지 않고 실패한다.

현재 `readArtifact`는 모든 엔트리를 메모리에 펼치므로 그대로 사용해 스트리밍이라고 부르지 않는다. 새 경로는 한 엔트리씩 해독하고 행 배열을 만들지 않는 파서를 사용한다. ZIP 버퍼와 현재 엔트리 해독 버퍼는 남을 수 있으며 메모리 측정에 포함한다. 과도한 입력 방지를 위해 초기 로컬 실행 제한은 ZIP 256 MiB, 엔트리 128 MiB, 총 해제 크기 1 GiB, 엔트리 64개다. 한도 초과는 명시적 실패로 보고한다.

## 5. 관측 검증과 월 집계

관측 계약은 `{ date: YYYYMMDD, hour: 0..23, dongCode: string, population: decimal }`이다.

- 날짜는 8자리 숫자와 실제 달력 날짜를 검증하고 기대 연월 안에 있어야 한다.
- 시간은 공백 제거 후 한두 자리 십진 정수만 허용한다. 0~23을 검증한 뒤 숫자로 정규화한다. `0`과 `00`은 같은 시간이다.
- 행정동 코드는 양끝 공백만 제거한 8자리 숫자 문자열이다. 선행 0을 보존한다.
- 총생활인구는 빈 값·`*`·null 표기·NaN·Infinity·지수 표기를 거부한다. 0 이상의 십진수이며 소수 자릿수는 최대 6자리로 제한하고 초과 시 반올림하지 않고 실패한다.
- 소수값은 10^6 배 정수로 변환해 BigInt로 더한다. 월평균은 합계/관측 수이며 출력에서 소수 여섯 자리까지 half-up 반올림한다. JSON에는 BigInt를 십진 문자열로 보존한다.

동별로 `날짜 인덱스 × 24 + 시간` 슬롯을 관리한다. 같은 값의 반복도 중복이며 오류로 처리한다. 월평균은 슬롯별 유효 관측의 산술평균이다. 각 동에 기대 관측 수(월 일수×24), 유효 고유 관측 수, 누락 수, 누락률, 최초·최종 날짜를 기록한다. 슬롯 하나라도 누락되면 그 동의 월평균 공개 값은 null이다. 부분 평균을 완결 평균처럼 제공하지 않는다.

기대 행정동 목록이 있으면 원본에 한 번도 나타나지 않은 동도 누락으로 찾는다. 목록이 없으면 관측된 동에 대한 완결성만 판정하고 `coverageStatus: observed_only`로 기록한다. 공식 서울 전체 커버리지 통과라고 표현하지 않는다. 월중 신설·폐지로 관측 기간이 짧은 동은 이번 MVP에서 완결 월 비교 대상에서 제외한다.

구조·타입·중복 오류가 있으면 해당 원본 실행 전체를 실패시켜 공개 후보를 생성하지 않는다. 형식은 정상이지만 관측 슬롯이 빠진 경우 동별 unavailable 결과를 생성한다. 실패 시 오류 종류별 건수와 엔트리·행 번호 최대 20건을 보존하고 전체 원문은 복제하지 않는다.

## 6. 동별 비교와 행정동 정책

비교는 같은 생활인구 계열의 현재 월·전년 동월·직전 월 세 후보로 수행하며, 후보 기간 자체가 맞는지 검증한다. 같은 OA ID와 헤더는 산출 방식 동일성의 충분한 증거가 아니다. 근거 매니페스트에 검토한 자료와 방법 버전을 기록한다. 근거 미확인은 `method_unverified`로 처리한다.

동별 순서는 다음과 같다.

1. 현재 월이 불완전하거나 실패하면 comparisonMode는 unavailable이다.
2. 현재 동과 전년 후보의 코드가 다르거나 존재하지 않으면 비교를 격리한다. 단순 코드 부재는 `administrative_area_unverified`, 공식 개편 근거가 있으면 `administrative_area_changed`다. 코드 부재를 이유로 임의 전월 대체하지 않는다.
3. 동일 코드라도 알려진 경계 변경이 있으면 비교 불가다. 같은 코드라는 이유로 반대 증거를 무시하지 않는다. 공식 이력이 없을 때의 비교 근거는 `same_code_only`로 기록하며 경계 동일성 확인이라고 표시하지 않는다.
4. 동일 코드·완결 관측·방법 및 의미 스키마가 호환되는 전년 후보를 우선한다.
5. 전년 후보의 방법/스키마 불일치 또는 관측 불완전으로 실패한 경우에만 같은 검사를 직전 월에 적용한다. 방법 미확인은 호환으로 간주하지 않으며 검증 가능한 직전 월이 있으면 대체 사유를 명시한다.
6. 직전 월도 실패하면 unavailable이다. 전년과 전월의 실패 사유를 각각 보존한다.

현재·후보 코드의 차이는 월 쌍마다 계산한다. 한 동의 격리가 다른 정상 동 비교까지 막지 않는다. 상권에 해당 코드가 없다는 이유만으로 생활인구끼리의 정상 비교를 막지도 않는다. 상권 연결은 별도 상태다.

출력은 동별 `comparisonMode`, `comparisonPeriod`, `fallbackReason`, `candidateFailures`, `codeMatchBasis`, 현재·이전 평균, 차이, 증감률을 포함한다. 이전 평균 0이면 차이는 계산하고 증감률은 null과 `previous_value_zero`로 표현한다. 코드 미확인 상태를 화면에서 확정적인 “행정구역 변경”으로 번역하지 않는다.

## 7. 저장 결과와 재현성

월 집계 파일은 동 코드 순으로 정렬한 집계·검증 상태를 담는다. 매니페스트에는 원본 해시·크기·공식 ID·기준월, 파서/스키마/방법/코드 목록/집계 버전, 엔트리별 포맷과 행 수, 오류 통계, 커버리지 상태, 결과 해시를 기록한다. 실행 시각·실행시간은 별도 실행 메타데이터로 두어 결정적 결과 해시에서 제외한다.

시간별 자료 전체는 영구 저장하지 않는다. 재처리는 보존된 원본과 동일 버전 설정으로 수행한다. 원본·작업 결과는 로컬 `data/raw/`, `data/work/`를 사용하고, Git에는 작은 합성 fixture와 검증 요약만 기록한다. 향후 R2에는 원본 및 매니페스트, D1에는 월 집계가 연결된다. 이 단계의 파일 출력을 서비스 공개로 간주하지 않는다.

출력은 임시 파일 완성 후 같은 파일시스템에서 이름을 바꾸는 방식으로 확정한다. 실패한 실행은 기존 정상 산출물을 덮어쓰지 않는다. 기존 프로파일과 `data:compare`는 원본 진단용으로 보존하고 새 정규화 비교를 별도 경로로 추가한다.

## 8. 검증과 완료 기준

- 같은 합성 관측을 월 단일 파일·일별 다중 파일·다른 엔트리 순서로 공급해 동일 집계를 확인한다.
- 쉼표/세미콜론·혼합 개행·코드 공백·선행 0과 `0`/`00` 중복을 검증한다.
- 빈 총생활인구, 비유한수, 음수, 소수 한도 초과, 잘못된 날짜, 다른 월, 시간 24, 잘못된 코드, 중복 헤더를 거부한다.
- 전체 행 수가 같아도 한 동의 누락과 다른 동의 중복이 있으면 통과하지 않는다. 기대 목록에만 있는 동 전체 누락, 윤년 2월, 진행 중 월을 검증한다.
- 월평균의 손계산 fixture와 입력 순서 독립성, 전년 우선·전월 대체·코드 격리·이전 0·방법 미확인을 검증한다.
- 실패 실행이 기존 산출물을 보존하는지 확인한다.
- 실제 202607·202507·202606을 다시 처리하고 동별 완결성, 코드 차이, 방법 근거 상태, 실행시간과 최대 메모리를 보고한다. 결과 수치를 미리 맞추지 않는다.

완료는 정규화가 검증되고 동별 비교 가능/불가를 근거와 함께 재현하는 상태다. 실제 원본의 방법 근거가 부족하면 해당 비교는 unavailable로 남긴다. D1 설계에는 검증된 계약을 전달하되 운영 공개 승인은 별도 검증을 필요로 한다.
