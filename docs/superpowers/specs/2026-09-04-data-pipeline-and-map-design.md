# 동네 변화 데이터 파이프라인·지도 설계

작성일: 2026-09-04 (Asia/Seoul)

## 1. 목적과 범위

서울특별시 행정동의 최근 1년 변화를 안정적으로 조회할 수 있도록 공공데이터 수집, 원본 보존, 검증, 집계, 화면 조회와 지도 비교의 경계를 정의한다.

이번 설계의 대상은 다음과 같다.

- 서울시 상권분석서비스 점포-행정동 데이터
- 250m 격자 기반 행정동별 서울 생활인구 내국인 데이터(OA-23016)
- 행정동 코드와 경계, 인접 행정동 관계
- 점포·개업·폐업·생활인구 변화 조회
- 선택 행정동과 인접 최대 4곳을 보여주는 지도
- 출처와 기준기간을 포함한 규칙 기반 요약

회원 기능, 실시간 데이터, 전국 확장, 지도 기반 자유 탐색, 생성형 AI 요약은 포함하지 않는다.

## 2. 확인된 원본과 표본 검증 결과

상권 원본의 공식 서비스명은 `VwsmAdstrdStorW`다. 공식 출력 필드는 기준 분기, 행정동 코드·이름, 서비스 업종 코드·이름, 전체·일반·프랜차이즈 점포 수, 개업률·개업 점포 수, 폐업률·폐업 점포 수다. 전체 점포 수는 일반 점포 수와 프랜차이즈 점포 수의 합이다. 2026-07-03 이후 2021년 이후 자료만 제공한다.

생활인구는 행정동별 내국인 자료만 사용한다. 현재 원본은 250m 격자를 행정동 단위로 집계한 OA-23016이며, 공식 전체 파일 목록에서 2023년 1월 이후 월 파일을 확인했다. Sheet와 Open API는 최근 2개월만 제공한다. 기본 비교는 최신 완결 월과 전년 같은 월이며, 두 파일의 산출 방식·필드 버전 또는 완결성이 일치하지 않을 때만 직전 월로 대체한다. 시간별 값을 합산한 고유 방문자 수로 표현하지 않는다.

2026-09-04에 상권 2025·2024와 생활인구 202607·202507·202606 실원본을 검증했다. 모두 EUC-KR이며 상권은 연도별 단일 쉼표 CSV, 생활인구는 32개 동일 헤더를 사용한다. 생활인구 202607은 일별 CSV 31개이고 7월 25~31일은 쉼표 헤더와 세미콜론 데이터 행을 함께 사용한다. 202507·202606은 월 단일 쉼표 CSV다.

상권 불변식과 세 생활인구 월의 날짜·시간·행정동 완결성은 통과했다. 다만 생활인구 파일 구성이 31개 대 1개로 다르므로 현재 엄격 비교는 `unavailable`이다. 월 단위 관측 집합으로 정규화하고 행정동 코드 변경을 판정하기 전에는 전년·전월 증감을 계산하지 않는다. 상세 측정값과 해시는 `docs/data/2026-09-04-source-sample-validation.md`에 기록한다.

## 3. 선택한 아키텍처

원본은 Cloudflare R2에 변경 없이 보존하고, 검증된 정규화·집계 결과만 Cloudflare D1에 공개한다.

```text
서울시 API·월별 파일
        ↓
R2 원본 저장 + 해시·출처 기록
        ↓
스키마·기간·코드·수치 검증
        ↓
정규화 + 월·분기 집계
        ↓
D1 임시 적재 및 검증
        ↓
현재 공개 스냅샷 교체
        ↓
Next.js 서버 조회/API
        ↓
요약 카드 + 인접 동네 지도
```

화면 요청에서 서울시 API를 직접 호출하지 않는다. 새 수집이 실패하면 기존 정상 공개 데이터를 유지한다. 일부 오류 행을 조용히 제외한 채 공개하지 않는다.

## 4. 기간과 지표 정의

### 4.1 상권

- 비교 기준: 최신 공개 분기와 전년 같은 분기
- 추이 기준: 비교 양 끝을 포함한 연속 5개 분기
- 전체 점포 수: 원본의 전체 점포 수
- 검증식: 전체 점포 수 = 일반 점포 수 + 프랜차이즈 점포 수
- 점포 증감: 현재 전체 점포 수 - 전년 동분기 전체 점포 수
- 증감률: 이전 값이 0보다 클 때 `(현재 - 이전) / 이전 × 100`
- 개업·폐업: 원본 건수와 원본 비율을 함께 보존

이전 값이 0이면 증감 건수는 표시할 수 있지만 증감률은 `unavailable`로 둔다. 누락이나 행정동 개편은 정상 증감과 분리한다.

### 4.2 생활인구

- 범위: 내국인 생활인구
- 기본 비교 기준: 최신 완결 월과 전년 같은 월
- 대체 비교 기준: 같은 OA-23016 계열이라도 산출 방식·필드 버전 또는 완결성 검증이 일치하지 않을 때 최신 완결 월과 직전 월
- 월평균: 유효한 날짜·시간별 총생활인구 관측값의 산술평균
- 증감: 현재 월평균 - 선택된 비교 월의 월평균
- 증감률: 이전 월평균이 0보다 클 때만 계산

월평균은 고유 방문자 수가 아니다. 화면에는 `내국인 생활인구 월평균`으로 표시하고 응답의 `comparisonMode`를 `same_month_previous_year` 또는 `previous_month`로 명시한다. 전월 비교로 대체할 때는 `fallbackReason`을 함께 반환해 전년 증감으로 오해하지 않게 한다. 연령·성별 세부값은 원본 검증에는 활용하지만 MVP 조회 결과에는 총합만 저장한다.

## 5. D1 데이터 모델

### `admin_dongs`

행정동 코드, 행정동명, 자치구 코드·이름, 유효 시작일·종료일, 경계 버전을 보존한다. 행정동명은 검색 표시값이고 조인은 코드와 유효기간으로 수행한다.

### `industry_categories`

카페, 음식점 등 화면에서 사용하는 업종 분류와 표시 순서를 보존한다.

### `industry_mappings`

서울시 서비스 업종 코드를 화면 업종 분류에 대응시킨다. 매핑 버전과 유효기간을 기록해 과거 집계를 재현할 수 있게 한다.

### `store_quarterly`

기본 키는 행정동 코드, 기준 분기, 원본 서비스 업종 코드다. 전체·일반·프랜차이즈 점포 수, 개업·폐업 건수와 비율, 출처 원본 ID를 보존한다. 화면 분류 집계는 업종 매핑 버전을 명시한다.

### `population_monthly`

기본 키는 행정동 코드와 연월이다. 월평균, 유효 관측 수, 기대 관측 수, 누락률, 최소·최대 관측일, 출처 원본 ID를 보존한다.

### `dong_neighbors`

기본 키는 기준 행정동 코드, 인접 행정동 코드, 경계 버전이다. 실제 경계를 공유하는 행정동만 저장하며 단순히 같은 자치구라는 이유로 인접 처리하지 않는다.

### `source_artifacts`

데이터 종류, 기준기간, 원본 URL 또는 공식 식별자, R2 객체 키, SHA-256, 바이트 크기, 수집시각, 파서 버전을 보존한다. API 키와 비밀값은 저장하지 않는다.

### `ingestion_runs`

실행 종류, 시작·종료시각, 상태, 입력 원본 ID, 파서·집계 버전, 읽은 행 수, 유효·오류 행 수, 공개 스냅샷 ID와 실패 사유를 보존한다.

## 6. 수집·검증·공개

1. 공식 API 응답 또는 파일을 수집한다.
2. 원본을 R2에 저장하고 SHA-256을 계산한다.
3. 파일 구조와 필드 타입을 검증한다.
4. 기간, 행정동 코드, 업종 코드와 수치를 검증한다.
5. 정규화 결과를 D1 임시 테이블에 적재한다.
6. 비교 기간 완결성과 집계 불변식을 검증한다.
7. 모든 검증이 통과한 실행만 현재 공개 스냅샷으로 교체한다.
8. 실행 결과와 통계를 `ingestion_runs`에 기록한다.

R2 객체 키는 데이터 종류, 기준기간, 수집일, 해시를 포함한다. 동일 해시를 재수집하면 새 원본을 중복 저장하지 않고 실행 기록만 남긴다.

### 상권 검증

- `분기 + 행정동 + 원본 업종` 중복 금지
- 점포·개업·폐업 수는 0 이상의 정수
- 전체 점포 수와 일반+프랜차이즈 합계 일치
- 원본 비율과 건수 기반 재계산 비율의 허용 오차 기록
- 연속 5개 분기 및 전년 동분기 존재 확인

비율 허용 오차는 원본 표본의 반올림 자리수를 확인한 뒤 파서 설정으로 고정한다. 표본 확인 전 임의의 허용 오차를 지정하지 않는다.

### 생활인구 검증

- `날짜 + 시간 + 행정동` 중복 금지
- 시간은 0~23시
- 생활인구는 0 이상의 유한수
- 월별 기대 일수와 시간대별 누락률 기록
- 현재 월과 전년 동월의 완결성 확인
- 전년 비교는 OA-23016의 같은 산출 방식·필드 버전인지 확인
- 전년 비교 검증 실패 시에만 직전 월의 완결성을 확인하고 대체 사유 기록

표본에서 완결 월은 `달력 일수 × 24 × 해당 월 유효 행정동 수`개의 고유 관측을 가졌다. 이 수식을 초기 완결성 기준으로 사용하되, 행정동 코드 유효기간을 먼저 적용한다. 기준 미달 월은 부분 수치로 공개하지 않고 `unavailable`로 처리한다.

### 행정동 검증

- 기준일에 유효한 코드인지 확인
- 코드 변경, 분할, 통합을 정상 증감과 구분
- 경계 버전과 통계 기준일의 대응 확인

자동 환산이 근거 없는 경우 이전 기간 비교를 제공하지 않는다.

## 7. 조회 인터페이스

### `GET /api/dongs?query={검색어}`

행정동명과 자치구명으로 검색한다. 응답에는 행정동 코드, 이름, 자치구 이름만 포함한다. 최소 검색 길이, 초성 검색과 동명이인 정렬은 화면 검색 설계에서 확정한다.

### `GET /api/dongs/{dongCode}/overview`

하나의 공개 스냅샷 안에서 다음을 반환한다.

- 행정동 기본정보
- 상권 현재·비교 분기
- 업종별 현재·이전·증감·증감률
- 개업·폐업과 5개 분기 추이
- 생활인구 현재·비교 월, `comparisonMode`, 선택적 `fallbackReason`과 월평균 변화
- 인접 최대 4개 행정동의 같은 지표
- 규칙 기반 요약 문장
- 데이터 출처, 기준기간, 수집시각과 결측 상태

서로 다른 스냅샷의 상권·생활인구 값을 한 응답에서 섞지 않는다. 최신 정상 공개 스냅샷이 없으면 HTTP 성공 응답에 0을 채우지 않고 명시적인 unavailable 상태를 반환한다. 잘못된 행정동 코드는 404로 구분한다.

## 8. 규칙 기반 요약

요약은 저장된 지표와 명시적 규칙만 사용한다.

- `카페 점포가 전년 동분기보다 8곳 늘었습니다.`
- `개업 수와 폐업 수가 모두 증가해 단순한 성장으로 해석하기 어렵습니다.`
- `내국인 생활인구 월평균이 전년 같은 월보다 2.1% 늘었습니다.`
- `전년 자료의 기준이 일치하지 않아 생활인구는 직전 월과 비교합니다.`
- `생활인구 자료가 불완전해 월간 비교를 제공하지 않습니다.`

점포 증가를 좋은 동네나 상권 성장으로 단정하지 않는다. 변화가 작거나 원본이 불완전하면 그 상태를 그대로 설명한다. 요약 문장과 숫자는 같은 응답 필드에서 생성해 불일치를 막는다.

## 9. 지도 설계

### 9.1 역할

지도는 선택한 행정동과 실제 경계를 공유하는 인접 최대 4곳을 비교하고 이동하는 인터페이스다. 서울 전체를 자유롭게 탐색하거나 정교한 길찾기를 제공하지 않는다.

### 9.2 기술

지도 렌더러는 MapLibre GL JS를 사용한다. 행정동 경계와 대표점은 버전이 기록된 GeoJSON 또는 벡터 타일로 공급한다. 배경 타일 URL과 스타일은 환경 설정으로 분리해 공급자를 교체할 수 있게 한다.

운영 환경에서 OpenStreetMap 공용 표준 타일에 직접 의존하지 않는다. 배경 타일 공급자는 사용 조건, 귀속 표시, 트래픽과 비용을 확인한 뒤 구현 단계에서 선택한다. 지도 엔진과 타일 공급자 선택을 분리한다.

### 9.3 표현과 상호작용

- 선택 행정동: 로즈 모브 반투명 면과 선명한 외곽선
- 인접 행정동: 낮은 채도의 파스텔 경계
- 대표점 배지: 행정동명과 선택 지표의 간략한 변화값
- 표시 지표: 점포 변화, 개업, 폐업, 생활인구 중 하나
- 선택 동 배지는 크게, 인접 동 배지는 작게 표시
- 배지 또는 경계 클릭 시 해당 행정동으로 전환하고 URL의 행정동 코드를 갱신
- 상세 수치는 지도에 겹쳐 넣지 않고 아래 카드에서 표시
- 겹치는 배지는 우선순위에 따라 숨기되 같은 내용을 목록에서 항상 제공

데스크톱에서는 요약 카드와 함께 보이는 높이를 사용하고, 모바일에서는 지도를 줄인 뒤 인접 동네 목록을 바로 아래에 둔다. 정확한 높이와 배치는 상세 화면 UI 설계에서 확정한다.

### 9.4 접근성과 대체 상태

- 지도와 같은 선택 기능을 키보드 접근 가능한 목록으로 제공
- 색상 외에 `+`, `−`, 라벨과 수치로 변화 방향 표현
- 배지의 최소 조작 영역 확보
- WebGL 미지원, 지도 스크립트 또는 타일 실패 시 인접 동네 목록 유지
- 지도 귀속 표시는 가리거나 접지 않음

## 10. 오류와 공개 상태

수집 실패, 검증 실패, 조회 불가, 지도 렌더링 실패를 서로 다른 상태로 기록한다.

- 수집 실패: 기존 공개 스냅샷 유지
- 검증 실패: 오류 원본과 사유 격리, 공개 금지
- 비교 기간 불완전: 해당 지표 unavailable
- 행정동 변경 근거 부족: 전년 비교 unavailable
- API 조회 실패: 오류 화면과 재시도 제공
- 지도 실패: 수치 카드와 인접 목록은 정상 유지

마지막 정상 갱신시각과 기준기간은 화면에 항상 표시한다.

## 11. 테스트 전략

### 단위 테스트

- 원본 파서와 타입 변환
- 상권 점포 합계 불변식
- 중복 키, 음수, 비유한수 거부
- 생활인구 월평균과 누락률
- 이전 값 0, comparisonMode와 unavailable 처리
- 행정동 변경 및 업종 매핑 버전
- 요약 문장 규칙

### 통합 테스트

- 실제 원본 표본 → 검증 → 정규화 → D1 임시 적재
- 실패 실행이 현재 공개 스냅샷을 바꾸지 않는지 확인
- overview 응답의 모든 값이 같은 스냅샷인지 확인
- 인접 관계와 경계 버전 일치 확인

### 화면·지도 테스트

- 검색 → 행정동 선택 → overview 표시
- 지도 배지 클릭 → URL과 상세 데이터 전환
- 지표 전환 시 배지 값 변경
- 모바일 배지 겹침과 가로 넘침
- 키보드 목록으로 같은 동 선택 가능
- WebGL·타일 실패 시 목록 대체
- 출처·기준기간·귀속 표시 확인

## 12. 외부 리소스와 연결 시점

실제 구현 전에 사용자가 Cloudflare 진행을 승인하면 R2, D1과 바인딩을 만든다. 지도 배경 타일은 공급자와 사용 조건을 확정한 뒤 필요한 키를 비밀 환경 변수로 설정한다. 저장소와 문서에는 키, 계정 ID 같은 비밀값을 기록하지 않는다.

Cloudflare 연결 전에도 로컬 fixture와 SQLite 호환 테스트로 파서·검증·집계를 구현할 수 있다. 실제 배포 검증은 Linux CI 또는 Workers 환경에서 수행한다.
